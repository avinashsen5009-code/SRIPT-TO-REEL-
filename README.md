# Reel Studio

Static, browser-based reel editor for 9:16 vertical and 16:9 landscape video. Host `index.html`, `manifest.json`, and `sw.js` together on any static HTTPS host. Upload narration or an audio/video file. With a blank script, uploading audio offers browser transcription. The first use of a chosen speech model requires an explicit download confirmation; alternatively paste a sentence-per-line script and choose **Build reel from script** with no speech model. Cancelling a transcription attempt does not necessarily abort a model transfer already in progress. Audio is required to time a reel. Script-based editing and built-in graphics require no API key or stock-photo service.

## Visual editing
Choose Balanced, Stickman-forward, Motion-graphics-forward, or Footage-forward. Each scene has an editable automatic treatment, a pinned treatment menu, the existing built-in visual picker, Replace media, layer toggles, reset, and move controls. User media is stored with browser projects (storage quota applies). Imported content remains the user's responsibility. The local scene planner emits an editable description in Scene JSON; uncertain interpretation is flagged rather than represented as a fact. Scenes use procedural canvas figures, arrows, cards, progressive flows, comparisons, steps, captions, and media annotations. Caption controls, music, voice recording, offline project storage, and export are retained.

For consistent fast export, Chrome/Edge with WebCodecs and the existing mp4-muxer fallback import are recommended. Fast MP4 muxing and optional auto-transcription load free third-party code/models if not bundled; the browser falls back to real-time export where supported. Hind and Kalam fonts are now bundled with their SIL Open Font License texts as root-level files; offline transcription and fast MP4 still require locally bundling the optional speech/model and muxer dependencies, or using a browser-supported fallback. No paid visual API is used. The service worker caches core files. Avoid importing unlicensed third-party assets.

## Known constraints
Scene understanding is rule-based (English/Hindi cues), not semantic AI. Pinned treatment and labels may need human review for ambiguous narration. Timing is estimated without aligned transcription. Video-file seeking and fast export are browser-dependent; fast export falls back to MediaRecorder for video clips. Browser storage may reject large projects.

## Structural minimalism style

The editor uses a separate `structural-minimalism.css` stylesheet: charcoal 40px grid, restrained grain, geometric 1px edges, masked heading reveal, and traced preview boundary. Select **Reel style → Structural minimalism** to render the *entire reel* in the matching monochrome grid style (including captions, scene diagrams, pinned library art, user media treatment, and music-mode visuals). This selection is saved in projects and used by the same canvas path for preview and video export. The palette deliberately overrides the colour theme selector while Structural minimalism is selected; other reel styles remain unchanged. Existing audio alignment and export controls are preserved. Do not remove the stylesheet when hosting.

## Word-level Structural renderer

`reel-renderer-minimalism.js` is loaded before the existing editor script. Only **Reel style → Structural minimalism** uses it. The style chooses one relevant built-in library object, procedural shape, or kinetic-type hero for each scene, then holds it while a small trace follows every timed word. When a library SVG is still loading or fails, a visible procedural tracer is shown instead. User-owned media is drawn in a bounded monochrome frame when that scene's media layer/treatment and visual direction select it. Its caption renderer reveals up to three words with each word triggered by the stored word-start timestamp; the supplied audio amplitude slightly affects vector/type motion. Other styles, upload, transcription, timing estimation, scene editing, and export implementations are unchanged.

These timings are only as accurate as the editor's supplied word timing. Without aligned transcription they are estimates; the engine uses an amplitude envelope, **not frequency-spectrum peak detection**. Review timing and captions before publishing. The fallback guarantees a visible treatment for a marker, not semantic certainty about an ambiguous word.

The built-in CSS and JS are served from the project folder; do not omit `reel-renderer-minimalism.js` or `structural-minimalism.css` from a deployment.


## Clearer timing and compact editing (current build)

Use the **◷ Sync** tool to adjust all narration visuals/captions by ±500 ms or the selected scene by 100 ms steps. Positive values display later. These corrections are saved in projects and applied by the shared preview/video render path and by SRT/VTT export. Open **▤ Captions → Advanced** to nudge an individual word onset by 50 ms or edit cue times. Caption words are corrected at their actual stored timestamps; the main scene visual now remains stable while the narration advances. Estimated timestamps can still drift if the transcript is not aligned to speech; review by listening.

The narrow-screen toolbar keeps **Sync, Captions, Music, Projects, and More** tools folded until opened. Tap a scene row to reveal its media, treatment, library picker, layers, reset and move controls. Motion has two basic settings: Calm & clear (default) and Standard. Sketch, Trending, Classic, Structural and the added Story style each keep distinct rendering behavior, while original visual pickers remain available.

## Handmade styles and landscape output (latest build)

The original four styles retain their existing figures, illustrations, stickers, media picker and caption editing. The Sketch diagram cards now resemble pencil-framed notebook pages, Trending uses anchored die-cut panels, Classic uses restrained engraved editorial frames, and Structural continues its monochrome scene-stable semantic artwork. Comparison and step diagrams can show small subject-matched hand-drawn objects, with labels taken from the script. These are **rule-based visual interpretations**, not verified depictions of every narration topic; review or replace any ambiguous scene. The time-remaining/progress strip has been removed from the actual rendered video; the editor waveform remains.

Choose **16:9 Landscape** beside the preview for a real 1280×720 or 1920×1080 render/export, not a stretched portrait frame. The left visual and right-side title, timed captions and script-derived relationship marks share the same scene timing and export path. Caption tap targets, safe-zone guide, saved project ratio, Scene JSON aspect ratio, uploaded media, and both export resolutions follow the selection. Portrait remains the default. Landscape is a designed recrop: review visual edges, captions, and title lengths before publishing. Changing the ratio does not change the original audio or transcription.

## Audio-first visual director (new)

When you upload audio with a blank script, Reel Studio asks permission before the first free speech-model download. After successful preparation it normally starts transcription automatically on later uploads with the same model, then builds an editable storyboard from the transcript. Transcription still depends on a model download if it is not bundled. It does **not** send audio to a paid visual API or invent unsupported visuals. After transcription, a local deterministic director looks for a concrete spoken subject, repeats it in relevant scene drawings, assigns purpose-led visual treatments, and exposes the inferred subject, confidence note, and four quick scene-treatment choices when you expand a scene. Captions, editable script, original picker/media, and all five selectable reel styles remain independent of this direction layer.

When the transcript does not identify a reliable subject, the automatic fallback is progressive typography using actual spoken words rather than a random object. Use the existing per-scene picker, upload media, or manually choose another treatment if you want a more literal illustration. Recognition errors, unfamiliar subjects, and metaphors still require human review. This is not a promise of accurate visuals for every possible topic from audio alone.

## Mobile speech setup and privacy (latest)

**Base multilingual** is selected by default for a smaller mobile download. **Small multilingual** is an optional, larger choice and may exceed some phones' memory. Each model has its own explicit first-use confirmation. A successful preparation is remembered for that browser/model in local storage; the model and runtime are requested from free external hosts and normally cached by the browser for later visits. Browsers can evict cached files, and a new phone, private session, cleared storage or changed model may download again. The model choice is remembered separately; no model weights are included in this ZIP. Browser transcription processes audio locally; the optional model files and runtime library come from external hosts. Offline reuse is device/cache dependent and **not guaranteed**.

If you provide your own script, the speech model is not loaded or downloaded. A site can be hosted on static HTTPS hosting and used from a phone while your own PC is off; hosting and download traffic still require an internet-connected site for first setup.

## Story: illustrated paper cards (new fifth reel style)

The **Story** style adapts the two supplied Story JavaScript files to the current editor without replacing its UI, saving schema, caption editor, audio pipeline, media controls, or export architecture. Warm textured paper, dark teal ink, orange/mustard accents, inset notes, expressive hand-illustrated character scenes and desk scenes form its visual language. Narration-driven cards can depict a list, sequence, comparison, dated timeline, a spoken number, or a *contextually supported* numeric comparison. Cut timing follows the existing scene/word timeline; uncertain meanings remain editable via the existing visual picker and per-scene treatment controls. The Story style keeps the same caption controls and tap targets as the other styles, with a dark pill backing for readability. It uses the same 9:16 and 16:9 export paths and saved-project style selection.

Unlike the older supplied drop-in, the integration **does not** overwrite the editor's global UI/CAP data, invent message/notification screens, fabricate graph values, or draw an in-video progress strip. The story frame uses the existing uploaded media, pinned library visuals and local music-mode artwork when selected. The original audio, transcription, timing, caption files, projects and four pre-existing styles remain intact. Story illustrations are editorial interpretations, not documentary evidence; check ambiguous depictions. Lora is bundled under SIL OFL as root-level files alongside Hind and Kalam.

Files changed for this style: `index.html` (fifth style, palette, ratio-aware drawing and a restored built-in SVG decoder), new adapted `story-director.js` and `story-style.js`, `fonts.css` plus `lora-variable.ttf` and `lora-OFL.txt`, `sw.js` (new cache version), `test-smoke.cjs`, and this README/`TEST_REPORT.md`. The user-supplied originals in `/home/user/uploads/` were not edited.

## Grounded visual explanations and visual-only review

The free, on-device `visual-grammar.js` layer looks for **explicit two-part relationships** within a scene: a spoken contrast, order, or cause, with two different subjects/actions recognizable in the existing built-in graphic library. Where both sides are found, the automatic treatment draws the actual relationship as two connected visual cards with source-matched pictograms, staged to the estimated spoken connector. It works in all five reel styles; repeated recognizable subjects reuse the same library artwork. The scene's **Explain spoken relationship** choice can be selected directly. Stickman-forward direction, pinned graphics, user media selected by the scene, manual treatments and original pickers remain available. When either side cannot be grounded, the engine falls back to the existing scene drawing and the scene information flags a relationship that needs review rather than inventing an icon, statistic or event. Scene JSON records the relationship, source words, and reason when it is unsupported. Changing a script can invalidate a previously chosen explanation; the scene then indicates that you should choose another treatment.

Click **◉ Visual-only review** beside playback to mute preview narration/music/imported-video sound and hide its captions; turn it off to return to normal review. This is a **temporary preview mode**, not a saved/export setting: MP4 audio/captions and SRT/VTT remain unchanged. It helps you judge whether the picture communicates the meaning without reading the caption. Short labels within the diagram are still visible. Audio-first builds still require transcription or a supplied script; the rule-based grammar is not a general image generator and will not accurately explain unfamiliar, implicit, abstract or poorly transcribed topics. Review every scene and replace it with your own drawing/media where needed.


## GitHub Pages: flat-file upload

The deployment is now deliberately **flat**: all required CSS, JavaScript, font files and font-license notices sit alongside `index.html` in one directory. Upload the extracted files, **not the ZIP**, to the root of a GitHub repository; leave every name unchanged. GitHub Pages can publish from `main` / `(root)` with no build step. `fonts.css` uses relative filenames in that same directory, and the service worker caches them there. Do not upload `node_modules`. The speech model and optional muxer are fetched separately on demand; they are not in the ZIP.

## Visual density and motion update

When captions are enabled, ordinary illustrated scenes now prefer a single recognizable source keyword beside a matching drawing rather than repeating long script fragments across title cards, stickers, and landscape side text. Unknown/abstract lines deliberately avoid claiming a literal picture. The 16:9 right panel now shows a sourced pictogram or a neutral mark instead of repeating the sentence and scene labels. The original per-scene label toggle, caption editor, user media, pinned graphics and manual typography treatment remain available; turning captions off preserves more of the original text-led treatments where appropriate.

The five styles still have their distinct main renderers: Sketch's stickman/notebook motifs, Trending's die-cut movement, Classic's engraved layout, Structural's monochrome tracing, and Story's illustrated paper/character scenes. Relationship diagrams now use vertically stacked paper/die-cut arrangements for Story/Trending and distinct horizontal treatments for the other three; adjacent scenes vary alignment. Shared source-matched library subjects are reused for continuity where explicitly recognized. **Calm & clear** uses a slower, smaller visual entrance; **Standard** reveals faster with a larger entrance/zoom. These settings affect preview and video imagery, **not** audio or caption timestamps. They cannot produce accurate bespoke animations for every arbitrary verb or abstract subject; please review and edit uncertain scenes.

## Automatic stickman scenes and portrait text density

In the 9:16 Sketch style—and in the Stickman-forward visual direction for its classic/trending canvas path—**automatic** scenes no longer reuse a stationary stickman beside a fixed rectangular diagram. Three deterministic scene stagings place the character left, right (mirrored so it points inward), or between explicitly spoken subjects, with a motion-profile-dependent entrance. Recognized objects come from the built-in graphic library; explicit contrasts and causes can be shown as icon-to-icon relationships without claiming unsupported details. Automatic Sketch scenes use no default panel box. A manually chosen Demo/Comparison/Steps treatment can still use its original boxes, and pinned graphics or selected footage keep their original priority. Drawing layers and the existing stickman remain editable.

When captions are visible, automatic 9:16 scenes now remove repeated noun labels from grounded icon diagrams rather than showing the same word in both the picture and caption. In visual-only review, short relationship labels return because captions are hidden. Manual text-led treatments remain accessible. No tool can reliably illustrate an unfamiliar topic or implicit action from speech alone; the editor flags and exposes uncertain scenes for manual editing.

## Explainer and Auto mix (browser-only)

Select **Auto mix: Story + Explainer** (new default) for deterministic, per-scene choices: people/place scenes favor the existing Story renderer; explicit chapters, comparisons, sequences, values, tools and technology favor Explainer. **Explainer: paper and blue** applies its own renderer to every scene. Existing Sketch, Trending, Classic, Structural and Story selections remain available. A small accent selector defaults to mustard and offers blue, green, orange and purple; the Explainer canvas can be warm paper or navy night. These selections, ratio, caption settings, audio, and per-scene edits are saved with the browser project. Explainer captions use the same editable word timestamps and SRT/VTT exporter as the existing styles. For 16:9, the art is composed into the existing landscape compositor and its caption tap targets remain editable.

Explainer's `explainer-style.js` has cached paper/night backgrounds and independent functions for TitleCard, BigStatement, CompareCards, FlowChips, ListCard, CounterCard, PhoneMock, WindowCard, FloatingChips, MiniScene, MetaphorProp, CTA and WaveformBar. Cards and timing are drawn locally on canvas; numeric comparisons only use explicitly spoken values, and CTA callouts only appear for an explicit call to action. The new component registry is `ExplainerStyle.components`. To add a component: write a function `(ctx, opts, plan)` inside `explainer-style.js`, register a lower-case treat key in `COMPONENTS`, and add a source-grounded selection rule to `StoryDirector.classifyText` in `story-director.js`. Keep geometry between y=140 and y=1020 in portrait, shorten or fit labels using the existing `fit`/`text` helpers, and test both canvas ratios before publishing. The Story renderer continues using its original `plan.eff.treat` values; `plan.explainer.treat` is separate.

**GitHub Pages:** The deploy ZIP has **no directories**: extract it and upload its individual root-level files, including `explainer-style.js`, `explainer-self-test.html`, font files, and `sw.js`. Select Pages → Deploy from branch → `main` / `(root)`. No build step or paid account/API is needed for canvas visuals. The optional Google-hosted Nunito face may load on an internet connection; local Hind/Arial fallbacks work when it does not. Optional browser speech-model and muxer downloads remain separate and may require internet. The service worker caches local core files for reuse but does not guarantee offline transcription.

**Review tool:** Open `explainer-self-test.html` on the hosted site. Its isolated embedded editor renders the **same 20 original sentences in both Story and Explainer** (40 real canvas previews), displays a contact sheet, and enables a PNG download. The page does not modify your open editor project; it uses a silent synthetic browser buffer, not recognized speech. The sample frames are editorial checks, not proof of universal topic comprehension. For unsupported phrases, the local director deliberately prefers a readable keyword or neutral shape rather than fabricating an event, chart, quotation or screenshot. Auto mix is not a semantic AI; transliteration, ambiguous terms, code-switching, long captions, device fonts and real speech timing still require human review. A measured fast desktop renderer is **not** a guarantee of sub-12-ms frames on every phone.

## Phase 1 scene graph (local, optional)

`scene-graph.js` uses the transcript to create editable, source-grounded nodes and links for explicit definitions, causes, cycles and hierarchies. Graph scenes can be viewed and edited in **Scene graph · inspect/edit** under a scene; turn on **Use graph** to preview in either Story or Explainer. **Apply graph** validates an edited JSON graph and saves it with the existing browser project. **Regenerate from this sentence** discards only that scene's manual graph and rebuilds it locally. The existing treatment dropdown, media picker, captions, and all other style paths remain available; turning graph off returns to the prior treatment. The graph's `at` fields are speech-word indices, not absolute seconds, and are linked to the same editable timings used by captions. The graphic region deliberately avoids the caption region. `scene-graph.js` must be uploaded beside `index.html` at the repository root and is included in the service-worker cache. No server, build step, or paid API is needed.

The graph is not a language-understanding guarantee: multiple concepts, implicit cause, unsupported languages, long labels, unusual sentence punctuation, word timing inaccuracies, or unrecognized spoken terms can need manual editing. The scene-inspector report checks its node rectangle geometry and nominal palette contrast, not pixel-perfect glyph boundaries. LLM direction is intentionally **not** bundled: a paid/remote director would contradict the no-paid-API requirement. Some requested engine subfeatures (full semantic primitives, genuinely intersecting Venn layout, mandatory eight-second interrupt, full automatic scene splitting, and measured sub-12-ms phone frames) are still pending or not verified. See `PHASE1_REPORT.md` for details.

## Phase 2 self-improvement (offline)

`self-improvement.js` extends the existing component registry for habits, focus, learning, routines, mindset and money habits. It only chooses a specific treatment when the local script contains a relevant cue. Under an applicable scene, open **Self-improvement · … · review** to disable that visual, edit its short labels, or restore spoken labels. The full narration still appears in captions; a shortened label is a reviewable suggestion, not a new quotation or statistic. You can still pin library visuals and change scene treatments. For GitHub Pages place `self-improvement.js` at the repository root beside `index.html`; it is precached by `sw.js`.

This is a rule-based visualization, not a fact-checker. A progress ring requires a spoken percentage; routine clocks without a spoken time intentionally omit hour hands; quotes require quoted words and never invent an author. An imperative checklist remains unticked unless completion is spoken. For full test results and the remaining Phase 2 limitations see `PHASE2_REPORT.md`.

## Phase 3 explainer / education (offline)

`educational-components.js` adds source-gated educational diagrams, charts and teaching cards to the existing Story/Explainer canvas and component registry. Open **Educational · … · review** under a scene to turn a treatment off or adjust its short labels. Numeric values and years stay tied to the original script, so editing a chart label must retain the spoken number; editing the transcript is the way to change the data. For quizzes, mark an answer in the script if you want a timed correct-option reveal; no answer is guessed. Locations, anatomy and cross-sections are clearly marked schematic. The script must be at the same GitHub Pages repository root as `index.html` and is included in `sw.js` (`reel-v31`). See `PHASE3_REPORT.md` for executed tests and limits.

## Phase 4: source-grounded metaphor props

`metaphor-props.js` adds 23 locally drawn vector props to Story and Explainer. It only proposes a prop when its literal English, Hindi or selected Roman-Hinglish phrase appears in a scene; separate spoken action cues determine whether the prop changes state. Unknown phrasing abstains. Expand a scene's **Metaphor prop · review** disclosure to leave it automatic, select the spoken prop or use the pre-existing treatment; this decision persists in browser projects. Educational diagrams, explicit graphs, chosen treatments and uploaded/pinned media retain priority. In landscape the right-hand subject panel displays the same prop. The module must be uploaded beside `index.html` and cached by `sw.js`; it uses no paid visual service. Full validation and limitations: `PHASE4_REPORT.md`.

## Phase 5: clarity tests and smaller, lower captions

**Captions** now allow 40–140% size and 45–82% portrait position (rather than 70–140% and 55–62%). Expand **Captions → Advanced** for the existing position and size sliders. The change follows projects into preview and export; landscape captions shift in their right-hand safe area. Use the **Show safe zones** switch to judge whether a low caption could be covered by a platform's controls. Mobile sliders are easier to touch. The waveform caches static artwork while playing, rebuilding for new audio, cut marks, theme colours and resize. No editor controls or existing styles were removed. Test scope and the distinction between nominal linter metrics and measured pixels are in `PHASE5_REPORT.md`.
